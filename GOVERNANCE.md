# Governance

This document describes how my personal open-source projects are maintained and
how decisions are made. It applies to any repository that does not ship its own
`GOVERNANCE.md`.

## Roles

### Maintainer

These are personal projects maintained primarily by
[@hasansezertasan](https://github.com/hasansezertasan). The maintainer has final
say over the project's direction, scope, and what gets merged.

### Contributors

Anyone who opens an issue, joins a discussion, or submits a pull request is a
contributor. Contributions of all sizes are welcome and appreciated.

## Decision making

- **Everyday changes** (bug fixes, docs, small improvements) are decided through
  normal pull request review by the maintainer.
- **Significant changes** (new features, breaking changes, changes in scope)
  should start as an issue or discussion so the approach can be agreed on before
  implementation.
- When there is disagreement, the maintainer makes the final decision, favoring
  the long-term health, simplicity, and maintainability of the project.

## Scope and roadmap

Each project's scope is defined by its `README.md`. Features that fall outside a
project's intended scope may be declined even if well-implemented — keeping
projects focused is a deliberate choice.

## Releases

Releases follow each project's stated versioning scheme (typically
[Semantic Versioning](https://semver.org/)). The maintainer decides when
releases are cut.

## Changes to governance

This document may be updated at any time. Material changes will be made through
a pull request so they are visible in history.
